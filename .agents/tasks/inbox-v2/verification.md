## Decisions on ambiguities

All decisions follow plan.md D1–D18. Points worth noting:
- **D1:** class collisions with the repo's `.role` and `.main` were avoided. The chip role span is `.rrole`; the split buttons are `.smain` and `.smore`. All new CSS is scoped under `.emailtable`, `#panel`, `#menu`, `#shade` or `#toast`.
- **D2:** no `.new` CSS was added, because step 10 was skipped.
- **D3:** invoice links on emails 2, 7 and 10 are `Received`, so that L4 (replace/remove) can be shown. Email 1 is `Invoice submitted`, for L6.
- **D4:** emails 12 and 11 are at the top, dated 30/10/2026.
- **D5:** strata plans, WOs, QRs and contractors use the repo's existing values plus the reference's contractors.
- **D8:** counters produce SR0005, QR002217 and WO620041.
- **D9:** in replace mode an SR link is set to Cancelled and kept; Remove link splices it. SR status is mirrored into `srRegistry`.
- **D10:** Undo restores both the email and `srRegistry`. Counters are not rewound.
- **D11:** the "Current" menu item is disabled.
- **D12:** the AI card shows Change on every email.
- **D13:** side-panel edits are saved to `e.fields`.
- **D14:** Save Draft only shows a toast.
- **D15:** SR details show Create QR/WO only while the SR is Open.
- **D16 `.statusline` (open point):** the "Confirmed Phase 1: … 24 h …" line under the table is **left unchanged**. It describes back-end duplicate rules rather than the removed test button, and nothing in cr01.md asks for it to go. The user should decide whether to remove it now that the 24-hour test lab is gone.
- **D17:** the unused `defaultContact` helper and the `.sideactions`, `.actionbar`, `.decision` CSS were left in place, because cr01.md does not list them for deletion.
- **D18:** `showDialog` buttons accept optional `id` and `disabled` (backward compatible).
- One addition beyond the plan: in `createForm`, the "From Service Request …" note ignores the SR link that is being replaced. Otherwise it would name SR0001 while SR0001 is about to be cancelled.
