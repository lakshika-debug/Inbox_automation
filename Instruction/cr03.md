## Duplicate handling

Existing Inbox behaviour, unchanged. The rules below apply it to the records this feature creates or links (SRs, quotes and invoices).
- Reprocessing or resynchronising the same email must never create another SR, or link the same quote or invoice again.
- A reply in the same thread inherits the original email's links (section 4) and is added to each record's email trail.
- Repeated request. A separate email from any sender is a repeated request when it names the same strata plan and the same lot, with the same service category, as an open SR (or an open QR or WO created from it). The AI does not create another SR.
    ◦ The email is flagged Action needed, the recommendation box reads "Repeated request: a Service Request already exists, **SR0004** (raised by [name], [date])" and recommends
    ◦ The Change and Dismiss are offered, if users need to take any action.
- No repeated-request check when the email states no lot or the issue is on common property: the same issue can come from different places in a building, so the AI creates the SR as usual.
- When the earlier record is completed, rejected or cancelled, the email is treated as a new request; the reason mentions the earlier SR.
